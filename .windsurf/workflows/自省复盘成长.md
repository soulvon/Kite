# 自省复盘工作流

> 触发时机：任务完成后，或用户主动执行 `/自省复盘成长`

## 第一步：收集信息

1. 回顾本次会话的完整对话记录
2. 查看当前系统规则：
   - 读取 `.agent/memory.md`（项目踩坑经验）
   - 读取 `AGENTS.md`（AI 助手工作流规则）

## 第二步：分析问题

检查以下维度，列出发现的问题：

| 检查点 | 具体表现 |
|--------|----------|
| **反复尝试** | 是否在某个问题上反复修改超过3次？ |
| **用户纠正** | 用户是否说过"我刚才说过"、"不是这样"等？ |
| **规则冲突** | 现有规则之间是否有矛盾？ |
| **规则缺失** | 本次遇到的场景是否缺少处理规则？ |
| **规则过时** | 哪些规则已不适用当前项目状态？ |

输出格式：
```markdown
### 发现的问题

1. **[问题类型]**：[具体描述]
   - 触发场景：[什么情况下发生]
   - 根因分析：[为什么会发生]
   - 建议规则：[新增或修改的规则文本]
```

## 第三步：分类建议（等待确认）

根据问题类型分类存放：

| 问题类型 | 存放位置 | 说明 |
|----------|----------|------|
| **踩过的坑** | `.agent/memory.md` | 项目特定的错误案例、技术细节 |
| **工作流规则** | `AGENTS.md` | AI 助手的通用行为规则 |

对每个问题，按优先级排序后逐个展示：

```
🔍 问题 #1：[简短描述]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📌 现象：
[本次会话中具体发生了什么]

📂 存放位置：
[.agent/memory.md 或 AGENTS.md]

🎯 建议修改：
[修改哪个部分，改成什么]

✅ 预期效果：
[改后能避免什么问题]

━━━━━━━━━━━━━━━━━━━━━━━━━━━━
请确认：[Y] 应用 / [N] 跳过 / [M] 修改建议
```

⏸️ **每个建议都要等用户确认，不要批量应用**

## 第四步：实施变更

对用户确认的每项变更：

1. 明确说明修改的文件和段落
2. 展示修改前 vs 修改后的对比
3. 使用编辑工具应用修改
4. 提交 git：`git commit -m "docs: 更新系统规则 - [简述改动]"`

## 第五步：记录复盘日志（可选）

将本次复盘的结论写入 `logs/reflect_YYYY-MM-DD.md`：

```markdown
# 复盘日志 - YYYY-MM-DD

## 本次会话任务
[简述本次任务]

## 发现的问题
[列出发现的问题]

## 应用的规则变更
[列出实际修改的内容]

## 未采纳的建议
[列出用户拒绝的建议及原因]
```

---

## 核心原则

1. **保守修改**：只改确定有问题的规则，不要过度优化
2. **具体优于抽象**：新规则要有"触发场景 + 具体做法 + 预期效果"
3. **增量进化**：每次复盘最多修改 3 条规则，避免大改
4. **可回滚**：每次修改都提交 git，方便回退
5. **分类存放**：踩坑经验放 `memory.md`，工作流规则放 `AGENTS.md`
