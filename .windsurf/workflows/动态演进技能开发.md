# 动态演进技能开发

一种支持**模块化设计** + **开发记忆** + **按需加载**的技能开发模式。

---

## 使用方法

```bash
# 了解此开发模式
/动态演进技能开发

# 进入某个技能的开发（读取已有进度）
/动态演进技能开发 spec/skills/PPT视频

# 创建新的动态演进技能
/动态演进技能开发 --new spec/skills/新技能名
```

---

## 核心理念

### 1. 模块化设计（减少上下文）

技能文档拆分为多个文件，AI 只加载需要的部分：

```
spec/skills/[技能名]/
├── 说明.md              # 🎯 主索引（必读，<200行）
├── design/              # 📐 设计文档（静态）
├── devlog/              # 📝 开发日志（动态记忆）
└── references/          # 📚 参考资源
```

### 2. 渐进式披露（Progressive Disclosure）

| 层级 | 内容               | 何时加载       |
| ---- | ------------------ | -------------- |
| L1   | 说明.md            | **新会话必读** |
| L2   | devlog/progress.md | **新会话必读** |
| L3   | 具体设计文档       | 开发对应模块时 |
| L4   | references         | 需要参考时     |

### 3. 记忆层（devlog/）

开发过程中持续更新，形成跨会话记忆：

| 文件           | 内容                       | 更新时机   |
| -------------- | -------------------------- | ---------- |
| `progress.md`  | 任务清单、完成状态、阻塞点 | 每次开发后 |
| `decisions.md` | 重要决策及其理由           | 做决策后   |
| `issues.md`    | 问题 + 解决方案            | 踩坑后     |
| `changelog.md` | 版本变更记录               | 阶段性更新 |

## 工作流程

### 进入已有技能开发

当用户使用 `/动态演进技能开发 <技能路径>` 时：

1. **读取索引**：
   - 读取 `<技能路径>/说明.md` 了解技能全貌
   - 读取 `<技能路径>/devlog/progress.md` 了解当前进度

2. **确认续接点**：
   - 向用户确认从哪个任务继续
   - 或询问用户想做什么

3. **按需加载设计文档**：
   - 根据当前任务，加载对应的 `design/*.md`
   - 不要一次性加载全部文档

4. **开发完成后更新记忆**：
   - 更新 `devlog/progress.md` 标记完成项
   - 如有重要决策，追加 `devlog/decisions.md`
   - 如踩坑，追加 `devlog/issues.md`

### 创建新的动态演进技能

当用户使用 `/动态演进技能开发 --new <技能路径>` 时：

1. **创建目录结构**：
   ```
   <技能路径>/
   ├── 说明.md
   ├── design/
   │   └── 01_产品定义.md
   ├── devlog/
   │   ├── progress.md
   │   ├── decisions.md
   │   ├── issues.md
   │   └── changelog.md
   └── references/
   ```

2. **填充模板内容**：
   - 在 `说明.md` 中填入技能基本信息
   - 在 `devlog/progress.md` 中初始化任务清单

3. **与用户确认范围**：
   - 询问技能的核心功能
   - 确定设计文档的拆分方式

## 文件模板

### 说明.md（主索引）

```markdown
# [技能名称]

> [一句话描述]

---

## 📊 开发状态

| 项目         | 状态           |
| ------------ | -------------- |
| **阶段**     | Phase N        |
| **进度**     | [当前任务]     |
| **阻塞**     | [阻塞点或"无"] |
| **最后更新** | YYYY-MM-DD     |

> 💡 详细进度见 [devlog/progress.md](devlog/progress.md)

---

## 🎯 产品概述

[简要描述技能做什么，3-5行]

---

## 📂 文档索引

### 设计文档（design/）
| 文件                          | 说明 | 何时读取 |
| ----------------------------- | ---- | -------- |
| [01_xxx.md](design/01_xxx.md) | ...  | ...      |

### 开发日志（devlog/）
| 文件                              | 说明     | 何时读取       |
| --------------------------------- | -------- | -------------- |
| [progress.md](devlog/progress.md) | 任务清单 | **新会话必读** |
| ...                               | ...      | ...            |
```

### devlog/progress.md

```markdown
# 开发进度

> 最后更新：YYYY-MM-DD

---

## 当前状态

| 项目         | 状态           |
| ------------ | -------------- |
| **阶段**     | Phase N        |
| **当前任务** | [任务描述]     |

---

## 下次继续

---

## 会话记录

| 日期       | 会话       | 完成内容   |
| ---------- | ---------- | ---------- |
| YYYY-MM-DD | [会话描述] | [完成内容] |
```

## 最佳实践

### 保持索引精简
- `说明.md` 控制在 200 行以内
- 只放索引和快速链接，详细内容放子文档

### 及时更新记忆
- 每次开发会话结束前，更新 `progress.md`
- 重要决策立即记录到 `decisions.md`

### 避免重复加载
- 同一会话内，已读过的文档不要重复读取
- 利用上下文记忆，只加载新需要的内容

### 问题优先记录
- 遇到问题时，先记录到 `issues.md`
- 即使暂时没解决，也留下记录供后续参考
