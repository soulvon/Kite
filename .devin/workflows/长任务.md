# 长任务自主循环

## 前置条件
- 用户有明确的大规模工作，需要多次迭代完成
- 支持两种模式：
  - **模式 A（批量重复型）**: 同一步骤 × N 个目标
  - **模式 B（项目构建型）**: 每个任务步骤不同

## 流程

### 1. 读取技能文档
// turbo
读取技能说明：`e:\project\GenStudio\.agent\skills\长任务\SKILL.md`

### 2. 判断任务模式
向用户确认：
- 每个子任务的步骤是否基本相同？
  - 是 → **模式 A**（步骤写 prompt.md，PRD 只列清单）
  - 否 → **模式 B**（PRD 每个任务写详细说明和验收标准）
- 需要处理的文件/模块/功能点总量
- 质量验证标准
- 已知的坑或约束

### 3. 收集项目材料
收集以下信息用于生成文件：
- 项目规则文件（GEMINI.md / rules.md）
- 相关架构文档
- 模式 A：需要处理的文件列表（用 `find` / `ls` 生成）
- 模式 B：功能规格描述或需求文档
- 核心 TypeScript 接口定义（推荐）

### 4. 生成四个协调文件
基于模板和项目材料生成：
- `prompt.md` — 参考 `e:\project\GenStudio\.agent\skills\长任务\templates\prompt.md`
- `PRD.md` — 参考 `e:\project\GenStudio\.agent\skills\长任务\templates\PRD.md`
- `progress.txt` — 参考 `e:\project\GenStudio\.agent\skills\长任务\templates\progress.txt`
- `friction-log.md` — 参考 `e:\project\GenStudio\.agent\skills\长任务\templates\friction-log.md`

### 5. 审查与迭代
让用户审查生成的文件，确认：
- prompt.md 的规则是否完整
- PRD.md 的任务拆分是否合理
- 模式 B：每个任务的步骤和验收标准是否清晰
- 模式 B：任务间的依赖关系是否正确
- ⚡ 当前阶段指针是否正确

### 6. 开始执行
文件确认无误后，按核心循环开始第一次迭代。
