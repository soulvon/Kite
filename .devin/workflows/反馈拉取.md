# 反馈拉取工作流

## 前置条件
- `.env` 中有 `SUPABASE_URL`
- `.env.local` 中有 `SUPABASE_SERVICE_KEY`

## 步骤

// turbo
1. 执行拉取脚本，从 Supabase 下载未处理的反馈、截图和日志：
```bash
node .agent/skills/feedback-pull/scripts/pull.mjs
```

2. 读取生成的原始数据文件 `spec/feedback/raw-{今天日期}.json`，分析所有反馈内容。

3. 对每条反馈进行 AI 分类：
   - **类型**：bug / feature / question / other
   - **优先级**：P0（崩溃/数据丢失）/ P1（功能异常）/ P2（体验优化）/ P3（建议）
   - **摘要**：一行描述
   - **去重**：识别描述相似问题的反馈

4. 如果有截图（`spec/feedback/attachments/{id}/screenshot.webp`），查看截图辅助判断。

5. 如果有日志（`spec/feedback/attachments/{id}/logs.json`），分析日志中的错误信息。

6. 更新报告文件 `spec/feedback/report-{日期}.md`，按优先级排列，格式如下：

```markdown
# 反馈分析报告 — {日期}

| 统计     | 数量 |
| -------- | ---- |
| 总反馈   | X    |
| Bug      | X    |
| 功能建议 | X    |
| 去重合并 | X    |
| 独立设备 | X    |

## 🔴 P0 - 紧急
无

## 🟠 P1 - 重要
1. **[bug] 导出卡在 99%** — 设备 F476, 版本 v0.1.23

## 🟡 P2 - 优化
...

## 🟢 P3 - 建议
...
```

7. 输出分析结果摘要给用户。
