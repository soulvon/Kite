# 版本发布工作流

当用户调用 `/版本发布` 时，按以下步骤执行完整的版本发布流程。

---

## 步骤 1：读取当前版本号

// turbo
从 `package.json` 中读取当前 `version` 字段值（如 `0.1.6`）。

```shell
Get-Content package.json | Select-String -Pattern '"version"'
```

---

## 步骤 2：计算新版本号

将 patch 版本号 +1，例如：
- `0.1.6` → `0.1.7`
- `0.1.9` → `0.1.10`
- `0.2.0` → `0.2.1`

规则：只递增最后一位数字（patch），不改 major/minor。

---

## 步骤 3：获取上次提交到现在的所有改动

// turbo
查看自上次版本提交以来的所有 Git 提交记录，用于总结改动：

```shell
git log --oneline --no-merges HEAD...$(git log --all --oneline --grep="版本发布" -1 --format="%H" 2>$null || git rev-list --max-parents=0 HEAD)
```

如果上面的命令找不到上次版本发布的提交，则回退为获取最近的提交：

```shell
git log --oneline --no-merges -n 30
```

---

## 步骤 4：AI 总结改动

根据步骤 3 获取到的 Git 提交记录列表，使用 AI 能力将这些提交按功能模块分类总结。

### 总结格式要求：

```markdown
## v{新版本号} ({当前日期 YYYY-MM-DD})

### ✨ 新功能
- 模块名：功能描述

### 🎨 界面优化
- 模块名：优化描述

### 🔧 修复
- 模块名：修复描述

### ♻️ 重构
- 模块名：重构描述
```

### 分类规则：
- 提交信息包含 `feat` / `添加` / `新增` / `实现` → **✨ 新功能**
- 提交信息包含 `style` / `样式` / `界面` / `UI` / `优化` → **🎨 界面优化**
- 提交信息包含 `fix` / `修复` / `修改` → **🔧 修复**
- 提交信息包含 `refactor` / `重构` / `迁移` → **♻️ 重构**
- 提交信息包含 `docs` 开头的跳过，不记录到日志
- 如果某个分类下没有内容，则省略该分类标题

### 模块识别规则：
- 涉及 `editor` / `timeline` / `剪辑` / `花字` / `变速` → **剪辑编辑器**
- 涉及 `browser` / `浏览器` → **内置浏览器**  
- 涉及 `tts` / `asr` / `语音` → **语音服务**
- 涉及 `template` / `模板` → **模板系统**
- 涉及 `agent` / `智能体` / `gemini` → **AI 智能体**
- 涉及 `publish` / `发布` → **发布管理**
- 涉及 `skill` / `技能` → **技能系统**
- 涉及 `download` / `下载` / `采集` → **视频下载**
- 涉及 `toolbox` / `工具` → **工具箱**
- 涉及 `settings` / `设置` → **系统设置**
- 涉及 `build` / `打包` / `安装` / `installer` → **打包部署**
- 其他 → **通用**

---

## 步骤 5：更新版本更新日志

读取现有的 `版本更新日志.md` 文件，将步骤 4 中总结好的新版本内容**插入到文件顶部标题行之后**（即 `# GenStudio 版本更新日志` 和 `---` 之后，旧版本内容之前）。

**注意**：保留所有旧版本日志内容不变，只在顶部追加新版本。

---

## 步骤 6：同步版本通知数据

将步骤 4 中总结好的更新内容同步写入 `src/constants/changelog.ts` 文件。

在 `CHANGELOG` 数组的 **最前面（索引 0）** 插入一个新的版本条目，格式如下：

```typescript
{
  version: '{新版本号}',
  date: '{当前日期 YYYY-MM-DD}',
  highlights: [
    // 从步骤 4 总结中提取 3 条最重要的亮点
  ],
  sections: [
    {
      title: '模块名',
      icon: '对应 emoji',
      items: [
        { emoji: '✨', text: '功能描述' },
        // ...
      ],
    },
    // ...
  ],
}
```

### 模块图标映射：
- 剪辑编辑器 → 🎬
- 语音服务 → 🎙️
- AI 智能体 → 🤖
- 内置浏览器 → 🌐
- 视频下载 → 📥
- 发布管理 → 📅
- 技能系统 → 🛠️
- 工具箱 → 🔧
- 系统设置 → ⚙️
- 环境管理 → ⚙️
- 打包部署 → 📦
- 重构与优化 → ♻️
- 通用 → 📦

### 变更类型 emoji：
- 新功能 → ✨
- 修复 → 🔧
- 重构 → ♻️
- 界面优化 → 🎨
- 性能优化 → ⚡

**注意**：保留所有已有的版本条目不变，只在数组最前面追加新版本。

---

## 步骤 7：更新 package.json 版本号

将 `package.json` 中的 `version` 字段值从旧版本号修改为新版本号。

例如：`"version": "0.1.6"` → `"version": "0.1.7"`

---

## 步骤 8：Git 提交

将所有更改提交到 Git：

```shell
git add package.json 版本更新日志.md src/constants/changelog.ts
git commit -m "release: v{新版本号} 版本发布"
```

---

## 步骤 9：确认完成

向用户汇报：
1. ✅ 版本号已从 `{旧版本}` 升级到 `{新版本}`
2. ✅ 版本更新日志已更新（`版本更新日志.md`）
3. ✅ 版本通知数据已同步（`src/constants/changelog.ts`）
4. ✅ Git 已提交（显示 commit hash）
5. 📋 显示本次更新的摘要内容

---

## ⚠️ 注意事项

- 工作目录是 `E:\project\GenStudio`
- 如果工作区有未暂存的更改，先提示用户是否需要先提交这些更改
- 日期格式使用 `YYYY-MM-DD`
- 所有界面文字使用中文
- 版本号遵循语义化版本规范 (SemVer)，本工作流仅递增 patch 版本
- 如果用户指定了版本号（如 `/版本发布 0.2.0`），则使用用户指定的版本号而不是自动递增

## ⏰ 构建有效期提醒

每次执行 `npm run build:electron` 编译生产版本时，会自动在控制台打印构建授权信息：

```
============================================================
  🔒 构建授权信息
  📅 编译时间：2026/4/9 05:09:00
  ⏰ 过期时间：2026/4/29 05:09:00
  📆 有效期：20 天
============================================================
```

编译出来的版本在 **20 天后自动过期**（`BUILD_HARD_EXPIRE` 常量烧入代码），过期后用户需要安装新编译的版本。
